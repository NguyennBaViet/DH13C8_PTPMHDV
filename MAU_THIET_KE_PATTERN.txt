2. STATE MACHINE PATTERN - BOOKING & PAYMENT LIFECYCLE
================================================================================

BOOKING STATE MACHINE:
═════════════════════

┌──────────────────────────────────────────────────────────────────────┐
│                         BOOKING STATES & TRANSITIONS                │
└──────────────────────────────────────────────────────────────────────┘

                              ┌──────────┐
                              │  START   │
                              └────┬─────┘
                                   │ [User clicks "Book Now"]
                                   ▼
                        ┌──────────────────────┐
                        │  PENDING             │
                        │ (Waiting for Payment)│
                        └──────────────────────┘
                          │              ▲
        ┌─────────────────┘              │
        │ [Payment Success]      [Payment Timeout (24h)]
        │                                │
        ▼                                │
    ┌──────────────────────┐             │
    │  CONFIRMED           │◀────────────┘
    │ (Booking Confirmed)  │
    └──────┬───────────────┘
           │
    ┌──────┴──────┐
    │             │
    │ [Check-in]  │ [User Cancel]
    │             │
    ▼             ▼
┌──────────┐  ┌────────────┐
│COMPLETED │  │ CANCELLED  │
│(Finished)│  │(Refunding) │
└──────────┘  └────────────┘

State Definitions:

1. PENDING (Chờ Thanh Toán)
   - Điều kiện vào: User click "Book Now"
   - Hành động: Tạo booking record
   - Timeout: 24 giờ (tự động cancel nếu không thanh toán)
   - Có thể chỉnh sửa: ✓ Có
   - Có thể hủy: ✓ Có
   - Chuyển tiếp:
     * → CONFIRMED (nếu thanh toán thành công)
     * → CANCELLED (nếu hết timeout hoặc user hủy)

2. CONFIRMED (Đã Xác Nhận)
   - Điều kiện vào: Payment SUCCESS
   - Hành động: 
     * Gửi email xác nhận
     * Giảm room availability
     * Tạo hóa đơn
   - Timeout: None
   - Có thể chỉnh sửa: ✗ Không
   - Có thể hủy: ✓ Có (tính hoàn tiền)
   - Chuyển tiếp:
     * → COMPLETED (khi quá check-out date)
     * → CANCELLED (nếu user hủy)

3. COMPLETED (Hoàn Thành)
   - Điều kiện vào: Check-out date đã qua
   - Hành động:
     * Gửi email cảm ơn
     * Tạo thông báo review
     * Cập nhật thống kê
   - Timeout: None
   - Có thể chỉnh sửa: ✗ Không
   - Có thể hủy: ✗ Không
   - Chuyển tiếp: NONE (Terminal state)

4. CANCELLED (Bị Hủy)
   - Điều kiện vào: User hủy hoặc timeout
   - Hành động:
     * Tính toán hoàn tiền
     * Gửi email thông báo
     * Tăng room availability
   - Timeout: None
   - Có thể chỉnh sửa: ✗ Không
   - Có thể hủy: ✗ Không
   - Chuyển tiếp: NONE (Terminal state)

State Machine Implementation (Java):

@Entity
public class Booking {
    @Enumerated(EnumType.STRING)
    private BookingStatus status;
    
    public void transitionTo(BookingStatus newStatus) {
        // Validate transition
        if (!isValidTransition(this.status, newStatus)) {
            throw new InvalidStateTransitionException(
                "Cannot transition from " + this.status + 
                " to " + newStatus
            );
        }
        
        // Execute actions before state change
        handleStateTransition(newStatus);
        
        // Update state
        this.status = newStatus;
    }
    
    private boolean isValidTransition(BookingStatus from, 
                                      BookingStatus to) {
        return VALID_TRANSITIONS.get(from).contains(to);
    }
}

PAYMENT STATE MACHINE:
══════════════════════

                            ┌──────────┐
                            │  START   │
                            └────┬─────┘
                                 │ [User submits payment]
                                 ▼
                      ┌──────────────────────┐
                      │  PENDING             │
                      │ (Processing Payment) │
                      └──────────────────────┘
                        │              ▲
        ┌───────────────┘              │
        │ [Stripe Success]    [Stripe Webhook Timeout (5min)]
        │                             │
        ▼                             │
    ┌──────────────────────┐          │
    │  SUCCESS             │◀─────────┘
    │ (Payment Completed)  │
    └──────┬───────────────┘
           │
      ┌────┴────┐
      │          │
      │          │ [User requests refund]
      │          │
      │          ▼
      │      ┌──────────────┐
      │      │  REFUNDING   │
      │      │ (Processing) │
      │      └──────┬───────┘
      │             │
      │             ▼
      │         ┌──────────┐
      ▼         │REFUNDED  │
   ┌─────┐     └──────────┘
   │ END │
   └─────┘

Payment States:

1. PENDING
   - Stripe request đang được xử lý
   - Webhook chưa nhận được
   - Timeout: 5 phút

2. SUCCESS
   - Stripe confirm thanh toán thành công
   - Webhook received
   - Booking được confirm

3. FAILED
   - Stripe reject thanh toán
   - Webhook received
   - User được thông báo lỗi

4. REFUNDING
   - Refund request đã gửi tới Stripe
   - Chờ webhook confirm

5. REFUNDED
   - Refund thành công
   - Tiền được hoàn lại user

1. Frontend Request
   POST /api/auth/login
   {
     "username": "user",
     "password": "pass"
   }
                        │
                        ▼
2. API Gateway receives → /api/auth/login
   - Check if needs authentication: NO (public endpoint)
   - Extract body
   - Log request
                        │
                        ▼
3. Gateway routes to Auth Service
   - Rewrite path: /api/auth/login → /login
   - Forward to http://localhost:8021/login
                        │
                        ▼
4. Auth Service processes
   - Validate credentials
   - Generate JWT token
   - Return response
                        │
                        ▼
5. Gateway receives response from Auth Service
   - Log response
   - Record metrics
   - Send back to client
                        │
                        ▼
6. Frontend receives response
   {
     "accessToken": "eyJhbGc...",
     "refreshToken": "eyJhbGc...",
     "expiresIn": 900000
   }

4. REPOSITORY PATTERN - DATA ACCESS ABSTRACTION

Repository Pattern Structure:

┌────────────────────────────────────────────────────────────────────┐
│                   SERVICE LAYER (Business Logic)                  │
│                      BookingService.java                          │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  @Service                                                          │
│  public class BookingService {                                     │
│      @Autowired                                                    │
│      private BookingRepository bookingRepository;                  │
│                                                                    │
│      public Booking createBooking(BookingRequest request) {        │
│          // 1. Validate input                                     │
│          validateBookingRequest(request);                         │
│                                                                    │
│          // 2. Create entity                                      │
│          Booking booking = new Booking();                         │
│          booking.setCheckIn(request.getCheckIn());                │
│          booking.setCheckOut(request.getCheckOut());              │
│          booking.setStatus(BookingStatus.PENDING);                │
│                                                                    │
│          // 3. Use repository to save                             │
│          Booking savedBooking =                                   │
│              bookingRepository.save(booking);                     │
│                                                                    │
│          // 4. Return result                                      │
│          return savedBooking;                                      │
│      }                                                             │
│                                                                    │
│      public List<Booking> getUserBookings(Long userId) {          │
│          // Repository handles DB query                           │
│          return bookingRepository.findByUserId(userId);           │
│      }                                                             │
│                                                                    │
│      public Booking updateBooking(Long id,                        │
│          BookingUpdateRequest request) {                          │
│          // 1. Find booking                                       │
│          Booking booking = bookingRepository.findById(id)         │
│              .orElseThrow(() ->                                   │
│                  new BookingNotFoundException());                  │
│                                                                    │
│          // 2. Validate state transition                          │
│          if (booking.getStatus() != BookingStatus.PENDING) {      │
│              throw new InvalidStateException();                   │
│          }                                                         │
│                                                                    │
│          // 3. Update fields                                      │
│          booking.setCheckIn(request.getCheckIn());                │
│          booking.setCheckOut(request.getCheckOut());              │
│                                                                    │
│          // 4. Save via repository                                │
│          return bookingRepository.save(booking);                  │
│      }                                                             │
│  }                                                                 │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────────────────┐
│            REPOSITORY INTERFACE (Data Access Contract)            │
│                   BookingRepository.java                          │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  @Repository                                                       │
│  public interface BookingRepository                               │
│      extends JpaRepository<Booking, Long> {                       │
│                                                                    │
│      // Find methods                                              │
│      @Query("SELECT b FROM Booking b WHERE b.userId = ?1          │
│             ORDER BY b.createdAt DESC")                           │
│      List<Booking> findByUserId(Long userId);                     │
│                                                                    │
│      @Query("SELECT b FROM Booking b WHERE b.hotelId = ?1         │
│             AND b.status = ?2")                                   │
│      List<Booking> findByHotelAndStatus(Long hotelId,             │
│                                        BookingStatus status);    │
│                                                                    │
│      // Custom query for date range                               │
│      @Query("SELECT b FROM Booking b WHERE b.checkIn >= ?1        │
│             AND b.checkOut <= ?2 AND b.status = 'CONFIRMED'")    │
│      List<Booking> findBookingsInDateRange(LocalDate from,        │
│                                           LocalDate to);         │
│                                                                    │
│      // Count methods                                             │
│      long countByStatusAndCreatedAtBetween(                       │
│          BookingStatus status,                                    │
│          LocalDateTime startDate,                                 │
│          LocalDateTime endDate);                                  │
│                                                                    │
│      // Exists check                                              │
│      boolean existsByIdAndUserId(Long bookingId, Long userId);    │

  - Testable with in-memory databases

Webhook Implementation:

@RestController
@RequestMapping("/api/webhooks")
public class StripeWebhookController {
    
    @Autowired
    private PaymentService paymentService;
    
    @Autowired
    private IdempotencyService idempotencyService;
    
    // Store webhook events for deduplication
    private Map<String, WebhookProcessingResult> 
        processedWebhooks = new ConcurrentHashMap<>();
    
    @PostMapping("/stripe")
    public ResponseEntity<Map<String, String>> 
        handleStripeWebhook(
            @RequestBody String payload,
            @RequestHeader("Stripe-Signature") String signature) {
        
        try {
            // 1. VERIFY WEBHOOK SIGNATURE
            // Prevents fake webhooks
            Event event = Webhook.constructEvent(
                payload, 
                signature, 
                STRIPE_WEBHOOK_SECRET
            );
            
            // 2. GET IDEMPOTENCY KEY
            // Unique identifier for this webhook event
            String idempotencyKey = event.getId();
            
            // 3. CHECK IF ALREADY PROCESSED (Idempotency)
            if (idempotencyService.isAlreadyProcessed(
                    idempotencyKey)) {
                // Return same response as before
                return ResponseEntity.ok(
                    Map.of("status", "already_processed")
                );
            }
            
            // 4. PROCESS EVENT
            switch (event.getType()) {
                
                case "charge.succeeded":
                    handleChargeSucceeded(
                        (Charge) event.getDataObjectDeserializer()
                            .getObject()
                            .orElse(null),
                        idempotencyKey
                    );
                    break;
                    
                case "charge.failed":
                    handleChargeFailed(
                        (Charge) event.getDataObjectDeserializer()
                            .getObject()
                            .orElse(null),
                        idempotencyKey
                    );
                    break;
                    
                case "charge.refunded":
                    handleChargeRefunded(
                        (Charge) event.getDataObjectDeserializer()
                            .getObject()
                            .orElse(null),
                        idempotencyKey
                    );
                    break;
            }
            
            // 5. MARK AS PROCESSED
            idempotencyService.markAsProcessed(
                idempotencyKey, 
                "success"
            );
            
            // 6. RETURN SUCCESS
            return ResponseEntity.ok(
                Map.of("status", "received")
            );
            
        } catch (SignatureVerificationException e) {
            // Invalid signature - possible attack
            log.error("Invalid Stripe signature", e);
            return ResponseEntity.status(401).build();
        } catch (Exception e) {
            log.error("Webhook processing error", e);
            // Return 400 so Stripe retries
            return ResponseEntity.badRequest().build();
        }
    }
    
    private void handleChargeSucceeded(
            Charge charge, 
            String idempotencyKey) {
        
        // Get payment from DB
        Payment payment = paymentRepository
            .findByStripeChargeId(charge.getId())
            .orElseThrow(() -> 
                new PaymentNotFoundException()
            );
        
        // Update payment status
        payment.setStatus(PaymentStatus.SUCCESS);
        payment.setCompletedAt(LocalDateTime.now());
        payment.setIdempotencyKey(idempotencyKey);
        paymentRepository.save(payment);
        
        // Confirm associated booking
        Booking booking = bookingRepository.findById(
            payment.getBookingId()
        ).orElseThrow();
        
        booking.setStatus(BookingStatus.CONFIRMED);
        bookingRepository.save(booking);
        
        // Trigger notifications
        notificationService.sendBookingConfirmation(booking);
    }
    
    private void handleChargeFailed(
            Charge charge, 
            String idempotencyKey) {
        
        Payment payment = paymentRepository
            .findByStripeChargeId(charge.getId())
            .orElseThrow();
        
        payment.setStatus(PaymentStatus.FAILED);
        payment.setFailureReason(charge.getFailureMessage());
        payment.setIdempotencyKey(idempotencyKey);
        paymentRepository.save(payment);
        
        // Keep booking as PENDING
        // User can retry payment
        
        notificationService.sendPaymentFailed(payment);
    }
    
    private void handleChargeRefunded(
            Charge charge, 
            String idempotencyKey) {
        
        Payment payment = paymentRepository
            .findByStripeChargeId(charge.getId())
            .orElseThrow();
        
        payment.setStatus(PaymentStatus.REFUNDED);
        payment.setRefundedAt(LocalDateTime.now());
        payment.setIdempotencyKey(idempotencyKey);
        paymentRepository.save(payment);
        
        notificationService.sendRefundConfirmation(payment);
    }
}

IDEMPOTENCY SERVICE:
═══════════════════

@Service
public class IdempotencyService {
    
    @Autowired
    private IdempotencyKeyRepository 
        idempotencyKeyRepository;
    
    // Check if webhook already processed
    public boolean isAlreadyProcessed(String key) {
        return idempotencyKeyRepository
            .existsByKeyAndStatus(key, "PROCESSED");
    }
    
    // Mark webhook as processed
    public void markAsProcessed(String key, String status) {
        IdempotencyKey idempotencyKey = 
            new IdempotencyKey();
        idempotencyKey.setKey(key);
        idempotencyKey.setStatus(status);
        idempotencyKey.setProcessedAt(LocalDateTime.now());
        idempotencyKeyRepository.save(idempotencyKey);
    }
    
    // Cleanup old entries (older than 24 hours)
    @Scheduled(cron = "0 0 * * * *") // Every hour
    public void cleanupOldKeys() {
        LocalDateTime cutoff = 
            LocalDateTime.now().minusHours(24);
        idempotencyKeyRepository
            .deleteByProcessedAtBefore(cutoff);
    }
}

Idempotency Benefits:

✓ At-Least-Once Delivery
  - Even if Stripe sends webhook multiple times
  - Payment only processed once
  - No duplicate charges

✓ Reliability
  - Network failures don't cause duplicate processing
  - Safe to retry webhook handling

✓ Data Consistency
  - No race conditions
  - Database stays consistent

Webhook Retry Logic:

If Payment Service doesn't return 200 OK, Stripe retries:
- Immediately
- 5 seconds later
- 5 minutes later
- 30 minutes later
- 2 hours later
- 5 hours later
- 10 hours later
- 24 hours later

This ensures webhook eventually gets through.
